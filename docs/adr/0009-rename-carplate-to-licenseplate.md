# ADR-0009. Переименование поля CarPlate в LicensePlate по паттерну Expand and Contract

Статус – принято
Дата – 24.10.2026
Задача – CAMPUS-109

## Контекст

Сервис парковки хранит номер автомобиля в колонке car_plate таблицы parking_sessions. Камеры распознавания и другие сервисы кампуса используют название LicensePlate, поэтому поле нужно переименовать. Шлагбаум работает круглосуточно. Если остановить сервис даже на несколько минут, автомобили не смогут въехать или выехать.

Простая команда ALTER TABLE ... RENAME COLUMN выполняется мгновенно, но сразу ломает работающую версию сервиса. Во время поэтапного обновления в Kubernetes часть подов еще на старой версии и обращается к car_plate, а часть уже на новой. Любой из вариантов в этот момент получит ошибку.

## Решение

Переименование выполняется в три фазы по паттерну Expand and Contract. Сначала скрипт 01_expand.sql добавляет колонку license_plate, допускающую NULL, и индекс по ней. Версия v1.9.0 пишет номер сразу в обе колонки, а читает из новой с запасным значением из старой. После полного обновления скрипт 02_migrate.sql переносит исторические записи. Удаление car_plate (03_contract.sql) выполняется только в следующем релизе v1.10.0, когда ни один экземпляр сервиса уже не обращается к старой колонке.

В трассы добавляется тег campus.parking_session_id, а сам номер автомобиля в теги не попадает. Номер относится к персональным данным, и хранить его в системе мониторинга не нужно.

## Последствия

Положительное последствие – переименование проходит без простоя шлагбаума, а на каждом шаге до фазы Contract возможен откат одной командой kubectl rollout undo. Отрицательное последствие – на время перехода данные дублируются, а код репозитория временно усложняется двойной записью. Его нужно не забыть упростить в версии v1.10.0.

## Рассмотренные альтернативы

Переименование колонки в окно обслуживания с остановкой сервиса отклонено, потому что шлагбаум пришлось бы открывать вручную. Создание представления (VIEW) со старым названием поверх новой колонки тоже отклонено. Оно скрывает проблему и оставляет в схеме два названия на неопределенный срок.
